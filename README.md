# CDN-RUL -- reference implementation

Code for the manuscript:

> **Auditing the Validity of RUL Prediction Intervals under Cross-Condition
> Deployment: A Protocol and the CDN-RUL Reference Model**

The contribution of the paper is a **protocol and an audit of uncertainty
validity**, not an accuracy leaderboard entry. The code here reproduces every
number, table and figure in that audit.

## Data

The result artifacts backing the reported numbers -- per-seed metrics,
conformal and group-conditional coverage statistics, the engine-level
bootstrap, the reweighting test and its placebo control, and the
maintenance-policy outputs -- are deposited and citable:

> **10.5281/zenodo.22850160** -- https://doi.org/10.5281/zenodo.22850160

The deposit is also mirrored in this repository under `results/physdec/`, so
cloning the code is sufficient to reproduce the paper without a separate
download. The two are byte-identical; the deposited copy is the citable one.

Model checkpoints and the NASA datasets are not deposited: the datasets are
publicly available from the NASA Prognostics Data Repository, and checkpoints
are reproducible from the commands below.

### What has been verified

The reproduction path was executed end to end on the authors' machine, and the
numbers below are the evidence for the claim rather than an assurance:

- **Ten seed runs reproduce exactly.** Every subset was re-trained for seeds 42
  and 2024 with the configuration in `run_multiseed.py`. Ten `metrics_*.json`
  files were rewritten and every scientific value matched the pre-run state --
  `metrics_DS02_seed42.json` RMSE 5.318, `metrics_FD003_seed42.json` 16.526,
  `metrics_FD002_seed2024.json` 27.097 -- as did the sampled arrays (`mc_*.npz`)
  and the trained weights behind them.
  That statement is scoped by a freshness gate: only files whose timestamp moved
  past the run start are compared, and a run that touches nothing exits
  UNVERIFIED rather than passing. A comparison against a restored backup proves
  nothing, because the two sides are then the same bytes by construction.
- **The aggregates are the aggregates of those per-seed files.** Re-deriving
  `multiseed_stats.json` from the five committed `metrics_*_seed*.json` of each
  subset reproduces every mean±std exactly: DS02 6.157±0.602, FD001 16.427±0.746,
  FD002 27.436±0.416, FD003 15.932±0.672, FD004 26.899±0.259. The three seeds
  outside the re-run enter that arithmetic as committed inputs; they were not
  themselves re-trained in this verification.
- **Every command in `REPRODUCE.md` was run as written**, including the four
  Section 4.6/4.7 steps that earlier revisions of this file omitted.
- **Figures, tables and manuscript agree**: a consistency check asserts that
  numbers appearing in both a table and a figure match before the figure is
  drawn.

### What is not reproducible from this repository

The artefacts below are **not** generated by any command here, and nothing in the
analysis chain consumes them as inputs:

| Artefact | Why it cannot be regenerated |
|---|---|
| `ablation_FD001.json` | an early per-subset intermediate; no script reads it. The published ablation table comes from `ablation_unified_stats.json`, which `aggregate_ablation.py` does regenerate from `metrics_FD002_*`. |
| `plain_lstm_fd002_multiseed.json` | read only by an internal audit script, not by any result generator. |
| `effect_sizes.json` | none of its values appear in the manuscript. |
| `final_summary.json` | a single-run summary of the baseline and best-PhysDec runs; no script here writes it. The single-run comparison values in Section 4.5 and the earlier single-run baseline quoted in Section 4.1 are not backed by any file in this repository or in the data deposit. |

They are retained for provenance. A reader who needs them should treat them as
historical records, not as outputs of this code.

Checkpoints (`.pt`) are likewise not distributed: `REPRODUCE.md` starts from
training, so every downstream step is run against models this code produced.

## Reproducing the uncertainty audit

```bash
python src/conformal_eval.py DS02        # calibration + coverage (Table 3)
python src/bootstrap_ds02_engine.py      # engine-level intervals + effective n

python src/audit_coverage.py --demo      # the Section 5.3 reporting set, no input needed
python src/audit_coverage.py out.npz     # apply it to your own intervals
```

`audit_coverage.py` is the checklist of Section 5.3 in runnable form, so it can
be applied to an existing set of intervals without reimplementing it. It takes an
`.npz` holding `y_true`, `lower`, `upper` (plus `unit`, and `group` if
conditional validity is being claimed) and reports the measured coverage, an
i.i.d. interval beside a cluster-aware one, the design effect and effective
sample size, the per-unit coverage range and the per-group spread. `--demo` runs
two synthetic cases with identical point counts and marginal coverage, one
independent and one clustered, which differ by a factor of about six in effective
sample size. The correction is the standard survey design effect and is not
claimed as new; what the paper contributes is that the prognostic literature
reports coverage without it.

The second script is the one that reports the paper's Section 4.6 finding: the
DS02 test set holds 125,228 windows but only three engines, and consecutive
stride-1 windows share 49 of 50 timesteps. Resampling at the engine level puts
the **effective sample size at 477**, not 125,228, and makes the coverage
interval roughly forty times wider than a naive i.i.d. interval.

## Naming history

The framework is called **CDN-RUL** throughout the manuscript. Source files and
result artifacts retain the earlier working name `physdec` (e.g.
`src/physdec_model.py`, `results/physdec/`). These names were deliberately left
unchanged so that released code, checkpoints and result files remain mutually
importable and the reported numbers stay traceable to the scripts that produced
them.
